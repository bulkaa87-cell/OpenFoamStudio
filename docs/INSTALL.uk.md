# OpenFOAM Studio: встановлення і налаштування сервера

Цей довідник пояснює, як встановити OpenFOAM Studio на Windows і як підключити сервер Linux для розрахунків. Імена в прикладах (`server1`, `alice`, `100.x.y.z`) — лише приклади. Підставляйте свої.

## 1. Встановлення програми (Windows)

1. Завантажте `OpenFOAM-Studio-<версія>-windows-x64-setup.exe`.
2. Запустіть файл. Права адміністратора не потрібні: інсталятор ставить програму у вашу теку користувача (`%LOCALAPPDATA%\Programs\OpenFOAM Studio`).
3. Виберіть мову інсталятора і параметри:
   - **Значок на робочому столі** — ярлик на робочому столі.
   - **Налаштувати сервер для розрахунків після встановлення** — програма запуститься одразу з помічником сервера.
4. Натисніть **Встановити**, потім **Завершити**.

Програма тримає ваші файли тут:

| Що | Тека |
|---|---|
| Налаштування | `%APPDATA%\OpenFOAM Studio` |
| Кейси, проєкти, остання сесія, збережені сітки | `Документи\OpenFOAM Studio` |

Видалення (Параметри Windows → Програми → OpenFOAM Studio) прибирає лише програму. Налаштування, кейси і проєкти лишаються.

### OpenFOAM на цьому компʼютері (не обовʼязково)

OpenFOAM Studio запускає OpenFOAM у WSL (підсистема Linux для Windows), у Docker або на сервері. На вкладці **Запуск** натисніть **Пошук**, щоб знайти, що є на цьому компʼютері. Для великих сіток найкраще — сервер.

## 2. Підключення сервера: помічник

Відкрийте **Файл → Налаштувати сервер…**. Кроки помічника:

1. **Початок**: виберіть «Підключити готовий сервер» або «Підготувати НОВИЙ, порожній сервер Linux».
2. **Tailscale на цьому компʼютері**: помічник знаходить Tailscale і читає його стан.
   - Tailscale не встановлено: натисніть **Завантажити Tailscale** (офіційна сторінка https://tailscale.com/download), встановіть і увійдіть. Сторінка сама побачить зміну.
   - Вхід не виконано: натисніть **Увійти**. Сторінка входу відкриється у вашому браузері. Програма ніколи не питає пароль чи ключ авторизації (auth key).
3. **Скрипт налаштування** (лише для нового сервера): див. розділ 3.
4. **Вибір сервера**: виберіть компʼютер зі своєї мережі Tailscale (tailnet), імʼя з конфігурації SSH або введіть адресу (`server1.tail1234.ts.net` чи `100.x.y.z`). Введіть своє імʼя користувача на сервері.
   - **Проміжний сервер**: заповнюйте лише для сервера, якого немає в мережі Tailscale, але який є в локальній мережі іншого сервера. Приклад: компʼютери лабораторії `node1`…`node8` за `server1`. Тоді SSH спершу заходить на `server1` (ProxyJump).
5. **SSH-ключ і вхід**:
   - Ключа ще немає: натисніть **Створити SSH-ключ**. Помічник створить `~/.ssh/id_ed25519` без парольної фрази, бо програма заходить на сервер без запитань.
   - Натисніть **Скопіювати ключ на сервер**. Відкриється вікно терміналу. Введіть пароль сервера один раз. Програма пароля не бачить.
   - Натисніть **Перевірити вхід**. Має бути «Вхід за ключем працює».
6. **Перевірка сервера**: помічник читає, який OpenFOAM є на сервері (встановлений, Docker, Podman, версія), скільки ядер, памʼяті й вільного місця. На сервері він нічого не змінює.
7. Натисніть **Готово**. Програма запускатиме кейси на цьому сервері (Файл → Налаштування → Машини). Якщо треба, помічник допише запис `Host` у `~/.ssh/config` і збереже копію `config.bak-<час>`.

Та сама перевірка вручну, у терміналі:

```
ssh alice@server1 "echo ok"
ssh alice@server1 "ls /usr/lib/openfoam/"
```

Програма запускає кейс зі встановленим на сервері OpenFOAM (`/usr/lib/openfoam/openfoam2512`) або в образі Docker чи Podman (наприклад, `opencfd/openfoam-run:2512`). На сторінці перевірки виберіть, що брати, у полі **OpenFOAM для розрахунків**. З контейнером кожна команда OpenFOAM іде в `docker run` чи `podman run` цього образу — так само, як у **Розподілити між машинами**. Теки кейсів мають лежати в `~/openfoam-studio` на сервері (програма кладе їх саме туди). Для Docker обліковий запис має бути в групі `docker`.

## 3. Підготовка нового, порожнього сервера Linux

Помічник складає bash-скрипт для сервера. Виберіть параметри:

- Встановити Tailscale (офіційний скрипт `https://tailscale.com/install.sh`) і запустити `tailscale up`.
- Встановити й запустити SSH-сервер.
- Додати SSH-ключ цього компʼютера в `~/.ssh/authorized_keys`. Тоді копіювати ключ з паролем не треба.
- OpenFOAM v2512: пакет `openfoam2512-default` з openfoam.com (Ubuntu, Debian) або образ Docker `opencfd/openfoam-run:2512`.

Далі:

1. Натисніть **Зберегти у файл…** і збережіть `ofs-server-setup.sh`.
2. Перенесіть файл на сервер: флешка, `scp` або вставте текст у `nano ofs-server-setup.sh` у терміналі сервера.
3. На сервері, під обліковим записом для розрахунків, виконайте:
   ```
   bash ofs-server-setup.sh
   ```
4. `tailscale up` надрукує адресу входу. Відкрийте її в браузері й увійдіть тим самим обліковим записом Tailscale, що й на своєму компʼютері.
5. Наприкінці скрипт надрукує імʼя облікового запису й імʼя в Tailscale. Поверніться в помічник, натисніть **Далі** і виберіть сервер.

Скрипт бере `sudo` для пакетів. Його можна запускати повторно: зроблене він пропускає. Програма цей скрипт ніде не запускає сама.

## 4. Якщо щось не працює

### Tailscale показує «Connected», а SSH зависає

Tailscale може показувати «Connected», коли шлях до сервера не працює. Дві відомі причини:

- **Застарілий ретранслятор (DERP).** Після сну або зміни мережі Wi-Fi компʼютер може тримати старий ретранслятор сервера. Виконайте `tailscale status`: після адреси видно `direct` або `relay "<регіон>"`.
- **Публічний Wi-Fi** (наприклад, безкоштовний Wi-Fi міста чи поїзда) може блокувати трафік Tailscale.

Кроки, по одному:

1. Спробуйте іншу мережу, наприклад точку доступу телефона або мережу університету.
2. Виконайте `tailscale netcheck` і подивіться рядок «Nearest DERP».
3. Перезапустіть службу Tailscale від імені адміністратора. У PowerShell (від адміністратора):
   ```
   Restart-Service Tailscale
   ```
   Або перезавантажте компʼютер.
4. Перевірте знову: `ssh alice@server1 "echo ok"`.

### «ping -l 1400» не проходить

Ця перевірка нічого не показує. MTU (найбільший розмір пакета) у Tailscale — 1280 байтів. Тому `ping -f -l 1400 100.x.y.z` не проходить завжди, навіть на доброму зʼєднанні. Найбільше значення для такої перевірки — 1252.

### Інші помилки SSH

| Повідомлення | Причина | Що робити |
|---|---|---|
| `Permission denied (publickey)` | На сервері немає вашого ключа | Скопіюйте ключ (крок 5 помічника) |
| `Could not resolve hostname` | Імʼя невідоме | Візьміть імʼя зі списку Tailscale або адресу `100.x.y.z`. Перевірте, що MagicDNS увімкнено |
| `Connection refused` | SSH-сервер не працює | На сервері: `sudo systemctl enable --now ssh` (Fedora: `sshd`) |
| `Connection timed out` | До сервера немає шляху | Див. «Tailscale показує Connected, а SSH зависає» |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | Ключ сервера змінився | Якщо сервер встановлено наново: `ssh-keygen -R server1`. Якщо ні — зупиніться і спитайте власника сервера |

## 5. macOS і Linux

Інсталятор — лише для Windows. На macOS і Linux запускайте програму з теки з кодом:

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python foam_studio.py
```

Помічник сервера працює так само. На macOS і Linux він не відкриває термінал для копіювання ключа, а показує команду (`ssh-copy-id` або `cat … | ssh …`): вставте її в термінал.
